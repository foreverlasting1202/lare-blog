# 一个 1.5B 模型怎样兼顾知识和数学？

从一条几乎不动的 GSM8K 曲线说起。预训练时放了多少数学题，这些题在参数更新里又占多大分量，是两个可以分开考察的问题。

## TL;DR {#tldr}

## 尝试训练一个既有知识又会数学的小模型 {#overview}

在读 [OLMo 2](https://arxiv.org/html/2501.00656v3#A2.T22) 和 [SmolLM3](https://huggingface.co/HuggingFaceTB/SmolLM3-3B-Base#base-pre-trained-model) 的技术报告的时候，我们注意到，单看预训练结束时的成绩，小模型在数学和代码上的分数都不是很高。但我们知道经过中训练后的模型，比如 Qwen2.5-Math，就会获得很高的数学分数。那如果我们混入更多的数学题，能不能直接预训练出一个更会推理的小模型？

所以我们尝试用 Nemotron 的混合语料训练了一个 1.5B 模型。在配置数据比例的时候，我们让网页文本、网页问答和网页数学各分到 70B tokens，科学和代码各分到 1B。网页和问答合起来正好是数学的两倍（2∶1）。算上科学和代码，数学约占总配料预算的 33%。

我们希望模型能多解出几道数学题，同时知识类问题也依然会做。为此，每次训练都跟踪两项评测，一项是 [GSM8K](https://arxiv.org/abs/2110.14168)，看模型能解出多少道数学应用题，另一项是 [MMLU](https://arxiv.org/abs/2009.03300)，看它对历史、生物等学科的知识掌握得怎样。

<!-- figure:april-pilot -->

但是实际训下来，模型能答对的知识题确实多了起来，训练 loss 也在下降，唯独 GSM8K 的曲线几乎没动。

### 训练 loss 里看不见什么？ {#diagnosis}

一道应用题的解答有许多 token。哪怕模型只是更熟悉解答里的惯用写法，平均 loss 也可能降下来。GSM8K 看的是最后算出的答案，前面写得再像，最后一步算错，这道题仍然是零分。我们也怀疑过，模型会不会已经能算，只是不熟悉答题格式？试着在提示词里放进几道解题示例，成绩依旧没多少起色。

还有一件事，从训练语料里数题目是看不出来的。一批数据送进去，数学题究竟给这一步参数更新贡献了多少梯度？后来我们用一个更小的 124M 模型专门测了这件事。这次只混两个领域，知识∶数学固定为 2∶1，也就是两份知识配一份数学。图里画的是每个领域在一批数据里产生的梯度范数。把它在各个线性层上的梯度合起来，就能比较知识和数学各占多大分量。

<!-- figure:domain-gradient-norm -->

刚开始训练时，两条线还交叉过几次。第 4,000 步以后，知识的梯度就开始稳定超过数学的梯度了。我们把每一次的知识梯度范数除以数学梯度范数，比值的中位数是 2.26。这就会有一种猜想，由于对于优化器而言，传入的梯度是平均后的梯度，因此如果知识的梯度比数学梯度大很多的话，可能就会出现平均导致数学梯度的信息被覆盖掉，从而只有知识梯度能产生作用。

这样再看最初的 1.5B 实验，倒有一个很直接的检验办法。把数学的比例一路加到只剩数学，看看 GSM8K 还会不会停在原地。

## 增大数学比例，能学会做数学题吗？ {#math-rich}

这一次，我们把 OpenR1-Math、OpenMathInstruct、NuminaMath 等来源的题目和解答汇在一起。为了尽量避免模型在训练时就见过测试题，我们先对这批数学语料做了去污，筛掉了与 GSM8K 等评测题目有大段文字重合的样本。

用这批语料，我们做了四组实验。其中一组只用数学，另外三组按不同比例混入维基文本。把数学统一记作 30 份，四种配方的「数学∶维基」分别是 30∶0、30∶1、30∶5 和 30∶10。

<!-- figure:math-rich-pilot -->

第一组在第 6,000 步的 GSM8K 就有 28.96%，第 42,000 步达到 69.22%。至少就这些应用题而言，1.5B 模型在预训练阶段是学得会的。

如果据此选配方，有个细节颇有意思。只看到第 6,000 步，30∶5 和 30∶10 两组的 GSM8K 都只有百分之十几，比纯数学慢了一截。把同一张图读到第 57,000 步，次序却反过来了。纯数学回落到 50.72%，后两组分别是 63.23% 和 62.32%。30∶0 这组应该是在同一批数学题上训了两遍（two-pass），我们怀疑后期这段回落与过拟合有关。再看这一步的 MMLU，后两组同为 26.76%，纯数学是 25.96%。最早学会做题的那份配方，到这里已经两项都落在了后面。

当数学比例低的时候，我们发现结果又会不一样。下图的两次训练用了相同的数学来源。绿线把数学和知识按 1:1 混合。蓝线则是数学和知识的配比降到了 1∶6。

<!-- figure:low-math-pilot -->

第 27,000 步，绿线已经到了 35.56%，蓝线还在 1.82%。单看这一段，我们很容易得出数学太少就学不会的印象。可是蓝线在第 33,000 步升到了 11.98%，之后又到了 15.01%。到第 57,000 步，蓝线已经到了 18.27%。

根据上面的结果，有一些很明显的结论：小模型在预训练阶段是绝对能学会数学的，只不过到底要怎么才能在兼顾知识的情况下，进一步提升数学能力呢？

## 配比与训练顺序 {#mixture}

预训练的配比怎么选，已有不少专门的研究。一种做法是先在小模型上选配方。DoReMi 让小模型学出采样比例，RegMix 用不同配方各跑一批小实验，再预测没试过的比例会有怎样的表现。也可以在训练中边看边调，Aioli 就利用各领域的 loss 来调整采样。至于某类知识需要在语料里占多少才学得进去，也有专门的实验。Gu 等人把合成人物传记混进网页文本，发现传记占比太低时，训很久也记不住多少传记里的事实。[DoReMi](https://arxiv.org/abs/2305.10429) · [RegMix](https://arxiv.org/abs/2407.01492) · [Aioli](https://arxiv.org/abs/2411.05735) · [知识学习与配比](https://proceedings.neurips.cc/paper_files/paper/2025/file/eee7ae5cf0c4356c2aeca400771791aa-Paper-Conference.pdf#page=2)

我们的实验只混知识和数学，所以只挑几个配比，直接在 1.5B 模型上各训一遍。训练预算固定为 30B tokens，优化器统一用 Muon，两类数据的 loss 权重都取 1。把知识∶数学从 7∶1 改为 3∶1，两项成绩一起涨，GSM8K 从 27.67% 到 43.67%，MMLU 从 31.40% 到 32.16%。再把数学加到 1∶1，GSM8K 还能涨到 59.89%，MMLU 却退回了 31.67%。

### 把两类数据分开学 {#forgetting}

即便定下了配比，也只定下了两类数据各有多少。拿 7∶1 来说，26.25B 知识 tokens 加上 3.75B 数学 tokens，可以一直混着训，也可以先把一类读完，再换另一类。我们把两种先后顺序都试了一遍，在切换前后用同一套题评测，看看后学的那门对先学的那门有多大影响。

<!-- figure:stage-history -->

先学数学，GSM8K 在切换前最高到过 18.50%，接下来只读知识，训完再做数学题，只剩 0.76%。把顺序颠倒，遗忘也跟着换了方向。先学知识时 MMLU 最高到过 31.08%，最后一段换成数学，GSM8K 升到了 36.62%，MMLU 降到了 29.45%。

### 两个峰值能不能同时保住？ {#mixing}

全程混合得到的终点落在这两种顺序之间。知识成绩大致保住了，GSM8K 也没有像最后只读知识时那样跌到接近零。这种折中的现象很符合我们之前的预期，也就是数学梯度容易被知识梯度覆盖掉信息，导致数学总是会少一些信息。那有没有办法使得数学信息不会就此消失呢？

## 配比怎样影响一次参数更新？ {#gradients}

不妨从一个具体的 batch 算起。一批有 128 个样本，其中 32 个来自数学。如果想把数学在更新里的分量加一倍，可以把数学样本加到 64 个，也可以照旧只取 32 个，把它们的 loss 乘以 2。在同一个参数位置算期望，两种办法确实都把数学的贡献加了一倍。如果我们仔细看梯度是怎么估出来的，差别就出现了。前一种办法多看了 32 个数学样本，相应地少看了 32 个知识样本，两边的抽样波动都会变。

把它写成普通 SGD 的更新式。设 batch 大小为 $B$，共享步长为 $\bar{\eta}$，领域 $j$ 的采样比例为 $p_j$，第 $t$ 步用该领域的 $n$ 个样本估出的平均梯度记作 $\hat{g}_{j,t}^{(n)}$。改配比，就是把 $p_j$ 换成 $p'_j$。如果保持配比，给该领域的 loss 乘上 $w_j$，则相当于给它一个单独的步长 $\eta_j$。

<!-- figure:mixture-updates -->

对照两行里的梯度估计，最值得留意的是它右上角括号里的样本数。改配比时，梯度前面的系数和这个样本数一起变。单独改步长时，样本数可以保持原样。这一点差别，会一直反映到训练结束时的 loss 上吗？

为了看清这个差别，我们在论文第 2 节选了一个能把最终损失算出来的例子。两个领域都做线性回归，输入 $x_j$ 服从均值为零、协方差为 $A_j$ 的高斯分布，标签为 $y_j = x_j^\top w^\star$。让两个领域各占一个参数子空间，而且彼此正交，即 $A_1 A_2 = 0$。用 SGD 训练 $T$ 步，分别计算两个领域的期望平方损失。

<!-- figure:orthogonal-loss -->

先取定配比 $(p_1, p_2)$，给每个领域选一个让自身最终损失尽可能小的步长 $\eta_j^\star$。另一边则换一组配比 $(p'_1, p'_2)$，仍让两个领域共用步长，但允许为新配比重新挑选这个步长 $\eta'$。在上述模型里，我们可以证明，无论怎样挑，下面两个不等式至少有一个成立。

<!-- figure:remix-bound -->

这两个不等式说的是，换了配比再调共享步长，至少有一个领域的最终损失会比原先单独选步长时更高。直观上，换配比总会让一个领域少分到一些样本。调大步长，可以让余下的样本对参数更新贡献更多，却补不回少抽样带来的估计误差。

图里是这个例子的一次数值计算。两个领域各占 512 个参数维度，每批 128 个样本，一共做 20 步 SGD。

<!-- figure:quadratic-frontiers -->

先看固定配比的那张图，采样比例是 1∶1，允许两个领域各选步长，就能找到一个点，让两边的损失同时降低。另一张图把所有测试过的配比放在一起看。取横轴上同一个损失值，允许分开选步长时，纵轴上的损失还可以更低。

线性回归确实能算得清楚，回到语言模型，知识和数学会改动同一批参数，AdamW 和 Muon 还要对汇总后的梯度做变换。前面我们在小模型上已经量到，两个领域的梯度范数常常差一截。回到 1.5B 模型，一个直接的检验办法是让它按完全相同的顺序读同一批数据，只给数学 loss 加个系数，看看两项成绩会往哪里走。

## 数学 loss 该乘几倍？ {#method}

### 从常数权重试起

前向计算已经给出了每个有效 token 的 loss。给属于数学的那些项乘上同一个系数，再对全批的有效 token 取平均，照常做一次反向传播就可以了。

我们沿用知识∶数学为 7∶1 的 1.5B Muon 模型。30B tokens 里有 3.75B 来自数学，各组前 20,000 步的 warmup 完全相同。此后把数学相对知识的权重分别固定在 1、2、3、4 或 7。

<!-- figure:remix-frontier -->

先看从 1 调到 2 的这一步。GSM8K 从 27.67% 升到 38.59%，MMLU 也从 31.40% 升到 32.27%。这两项都超过了分阶段训练的最高分（MMLU 31.85%，GSM8K 37.91%）。

系数再大一些如何？加到 7，GSM8K 还能到 48.98%，MMLU 却降到了 31.19%。在这份配方上，想兼顾两项成绩，2 已经相当合适。麻烦的是，这个数得把几个常数各训一遍才知道，换个配比或优化器又要重找。能不能只训一次，从训练过程中估出这个权重？

### 平方根从哪里来？ {#inverse-square-root}

设输入 $x\sim\mathcal N(0,I_d)$，取一个单位向量 $u$，用 $y_0=\operatorname{sign}(u^\top x)$ 把样本分成两类。再以概率 $\rho\in(0,1/2)$ 独立翻转每个标签，得到训练时看到的 $y$。对一个样本，logistic 回归的 loss 和梯度分别为

$$
\begin{aligned}
\ell(w;x,y)&=\log\!\left(1+e^{-y w^\top x}\right),\\
g(w;x,y)&=-\frac{yx}{1+e^{y w^\top x}}.
\end{aligned}
$$

沿 $w=ru$ 调整 $r\geq 0$，让总体 loss 取到最小值 $\ell_\rho^\star$。此时单样本梯度 $g$ 的期望为零，但它在各个方向上仍有波动。记它的协方差为 $\Sigma_\rho$。固定维度 $d\geq 2$，当 $\rho\downarrow 0$ 时，$\ell_\rho^\star=\Theta(\sqrt{\rho})$。沿分类方向 $u$ 和任一与之正交的单位方向 $v$，梯度的方差分别为

$$
\begin{aligned}
u^\top\Sigma_\rho u &= \Theta\!\left((\ell_\rho^\star)^2\right),\\
v^\top\Sigma_\rho v &= \Theta\!\left(\ell_\rho^\star\right).
\end{aligned}
$$

当 loss 很小时，一次项比平方项大，梯度的波动主要来自那 $d-1$ 个正交方向。把各方向的方差加起来，再开平方，就得到单样本梯度范数的均方根

$$
\sqrt{\mathbb E\lVert g\rVert^2}
=\sqrt{\operatorname{tr}\Sigma_\rho}
=\Theta\!\left(\sqrt{d\,\ell_\rho^\star}\right).
$$

现在给领域 $i$ 的 loss 乘上正权重 $w_i$。把这个领域的有效维度记作 $d_i$，加权后的梯度范数有多大？

$$
\operatorname{RMS}(w_i g_i)
=\Theta\!\left(w_i\sqrt{d_i\,\ell_i^\star}\right).
$$

如果各领域的有效维度和比例常数相近，取 $w_i\propto(\ell_i^\star)^{-1/2}$，恰好能抵消上式里 loss 的平方根因子。

语言模型训练时，最优 loss 当然无从得知。在 LARE 里，我们用训练时就能测到的量来近似它，也就是每个领域的平均交叉熵。warmup 期间各域权重都取 1，同时记录两个量的滑动平均，一个是加权前的 loss，另一个是实际参与预测的 token 数。warmup 结束后，对每个领域的平滑 loss 取平方根倒数，就得到了下式里的原始分数。

<!-- figure:weight-equation -->

式子里还多了一步归一化。按各领域有效预测位置的占比，对这些分数取加权平均，再让每个分数除以这个平均值。这样得到的权重，用同样的占比取平均，恰好是 1。下一步训练就用这组权重，照原配方采样。

现在可以对照一下自动算出的系数和手动挑的常数了。两种方法用的还是同一条 7∶1 数据流。

<!-- figure:adaptive-history -->

从第 25,000 步起，数学相对知识的权重平均是 2.30，最后停在 2.41。用这组随训练更新的权重，最终 MMLU 为 32.24%，GSM8K 为 39.80%。和固定取 2 相比，MMLU 低了 0.03 个百分点，GSM8K 高了 1.21 个百分点。

## 加入代码，把训练延长到 240B tokens {#results}

看到 30B tokens 的结果时，我们还想到另一种解释。LARE 的数学成绩更高，也许只是因为它学得快些。要是多训一阵，直接混合会不会慢慢追上来？

先把两域实验的预算加到 120B tokens，模型仍是 1.5B，知识和数学仍按七比一混合。

<!-- figure:long-scores -->

到了这个预算，直接混合的 GSM8K 是 37.00%，LARE 是 50.57%。换成更难的 MATH-500，两者分别为 17.20% 和 25.60%，MMLU 也从 33.97% 略升到 34.36%。给了四倍的训练量，两种方法在数学上的差距依然可见。

加上代码以后，我们仍把八份数据中的七份留给知识，将原先留给数学的那一份平分给数学和代码。举例来说，120B tokens 对应 105B 知识、7.5B 数学和 7.5B 代码，这里数的是做 loss mask 之前采到的 tokens。对照仍然在同样的模型、配比和训练预算下做，优化器都用 ActGD，只改变各领域的 loss 权重。另一对独立实验用 240B tokens。论文里所说的 4× 和 8× Chinchilla 就是指这两档预算，1× 取这个 1.5B 模型的 30B-token 预算。

<!-- figure:long-curves -->

在 120B 这一对实验里，MMLU 的两个成绩是 33.52% 和 33.53%，几乎分不出差别，GSM8K 却拉开了 14.79 个百分点。代码题也有收益，HumanEval 从 15.85% 升到 21.34%，MBPP 从 9.40% 升到 12.20%。

到了 8×，直接混合和 LARE 的 GSM8K 分别是 29.72% 和 46.78%，MMLU 分别是 34.13% 和 34.96%。这一次，五项评测都是 LARE 得分更高。如果五项各占相同分量，4× 时平均提高 5.90 个百分点，8× 时是 7.84 个。

从上述结果来看，很明显，LARE 会优于直接混合，这充分说明了这一套思路的有效性。

## 哪些数据该共用一个权重？ {#sources}

再看一眼 LARE 的公式。每个权重都来自一个平均 loss，可究竟该把哪些 token 放在一起取平均？前面的实验里，我们让所有数学题解共用一个权重，代码另算一个。但真实场景中，训练语料甚至可能有成千上万个来源，不好人工去划分。光是数学，不同题库的题型和解答写法就不尽相同。按来源各算一项 loss，看起来也很合理。

在同一条 32.71B-token 数据流上，我们用直接混合作对照，先比较两种加权方式。一种给知识、数学和代码各设一个权重，另一种给 18 个来源各设一个权重。

按领域和按来源有一个共同之处，都是先看数据叫什么名字，再决定哪些 token 放在一起。可在 LARE 的计算里，真正用到的是模型预测这些 token 时的 loss。两份来源完全不同的语料，模型读起来却可能一样容易。既然如此，何不让模型先读一遍，再决定怎样分组？

### 按校准 loss 分组 {#grouping}

直接混合模型训练到第 20,000 步时，warmup 刚结束。我们用它分别读每个来源留出的验证数据，只在参与监督的 token 上计算平均交叉熵。每个来源由此得到一个校准 loss。把 18 个来源按这个数从大到小排列，每三个相邻的分为一组。实验记录把 loss 最低的那组记作第 1 组，所以下图从高往低看，组号依次是 6 到 1。

<!-- figure:loss-groups -->

看排在最后的三个来源。MetaMath 的 loss 是 0.483，Swallow 是 0.543，Swallow Code 是 0.556。于是两份数学语料和一份代码语料分到了一组。反过来，同样是数学题的 MathInstruct，loss 却有 1.489，和 MetaMath 分属不同的组。

校准只做这一次。往后哪些来源在一起算平均就固定了，每组的系数仍会变。训练时按组汇总有效 token 的 loss，用 LARE 更新权重即可。

<!-- figure:group-curves -->

先看 GSM8K，直接混合是 14.25%，按知识、数学、代码三个领域加权是 22.97%，再细分到 18 个来源是 22.67%。MMLU 按同样的顺序分别为 32.47%、32.20% 和 32.35%。从三个权重增加到十八个，MMLU 多了 0.15 个百分点，GSM8K 少了 0.30 个百分点。细分之后，按领域加权带来的数学收益大体还在。只是把每个来源都单列出来，两项成绩并没有一起提高。

在同一条 32.71B-token 数据流上，这样分成六组，MMLU 是 32.74%，GSM8K 是 24.03%，比按三个语义领域分组分别高了 0.54 和 1.06 个百分点。在这次试过的几种分法里，六组的两项成绩都是最高的。

## 总结 {#conclusion}

最初看到 GSM8K 几乎不动时，我们想知道，给这个 1.5B 模型多读一些数学题，它究竟学不学得会？后来的高数学配比实验回答了这个问题。只靠预训练，模型就能做对不少数学应用题。难的是让它多做对几道数学题的同时，还记得之前学过的知识。把数学留到最后集中学，GSM8K 上去了，MMLU 却会回落。两类数据从头混到尾，两项成绩又落在两种训练顺序之间。

有一组对照让我们换了个问法。模型读的还是同一批数据，连顺序都一样，只把数学 loss 的权重从 1 调到 2，GSM8K 和 MMLU 就一起涨了。既然同样的题可以学得更好，接下来要找的就是这个权重。LARE 用各领域平滑后的 loss 的平方根倒数来定权重，省去了为每个候选系数各训一次的开销。加入代码、把预算加到 240B tokens 后，相比同配比的直接混合，GSM8K 仍然高出 17.06 个百分点，MMLU 也高了 0.83 个百分点。

最后一个实验又往前走了一步。我们用刚结束预热的模型给 18 个来源测了验证 loss，按高低排序，让相邻的三个来源共用一个权重。这样只用六个权重，MMLU 和 GSM8K 都比给每个来源单独配权重更高。回头看，最早我们只数了模型读过多少数学题，后来才发现，即便一道题也不换，光是调整这些题在参数更新里占的分量，就足以改变模型最后能做对多少题。
